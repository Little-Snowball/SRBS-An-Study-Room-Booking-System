# 后端内部开发契约（Internal Contract v1）

本文件是并行开发的唯一契约来源。所有后端模块必须遵守；与本文冲突的旧文档以本文为准。
技术基线：Java 21 / Spring Boot 3.5.16 / MyBatis 3.0.5 / MySQL 8 / Flyway / springdoc 2.8.17。

## 1. 包结构

根包 `edu.campus.studyroom`，模块：common, security, auth, user, resource, rule, reservation,
attendance, settlement, scheduler, credit, appeal, file, notification, notice, stats, audit, seed。
每个模块按 controller / dto / service / domain / mapper 分层；实体在 `<module>/domain`，
Mapper 接口在 `<module>/mapper`，XML 在 `backend/src/main/resources/mapper/`。

## 3. 时间与时钟

- 唯一可信时间源是注入的 `BusinessClock`；禁止在业务命令中混用数据库 NOW()。
- 实体与数据库用 `LocalDateTime`（Asia/Shanghai）；API DTO 的时间字段一律 `OffsetDateTime`
  （Jackson 已配置序列化为带 +08:00 的 ISO 串，反序列化拒绝无偏移输入）；date-only 用 `LocalDate`；
  TIME 字段用 `LocalTime`。
- 存取截止一律毫秒严格比较；`end` 用 `now >= end`，违约用 `now > due`。

## 4. 事务与并发协议（8.1/8.2）

- 核心写命令：`@Transactional(isolation = Isolation.READ_COMMITTED)`，方法第一行
  `businessGuardLock.lock()`，然后 `clock.nowLocal()` 取一次 now。
- 事务内重新校验：会话未撤销/用户 ACTIVE 且非 blocked/auth_version 一致。
- 幂等：先 `idempotencyService.checkInTransaction(userId, commandType, requestKey, hash)`
  （相同 key 不同参数抛 IDEMPOTENCY_KEY_REUSED；相同 key 已成功抛
  `IdempotencyService.IdempotentReplayException(resultType, resultId)`，由 Controller 捕获后
  按权限重新查询当前视图返回）；命令成功后 `recordSuccess(...)` 同一事务写入。
- 状态写入用 `ReservationMapper.updateState`（version 条件更新），affectedRows 必须为 1，
  否则 409 INVALID_STATE / 503 BUSY_RETRY。
- 补结算：Controller 先调用 `PreflightSettlementService`（独立事务提交），再调用命令 Service；
  命令 Service 内部发现已到截止也要就地补结算（复用 SettlementService.settleOne，同事务）。
- 异步/定时/管理端写核心表也必须走同一协议；禁止局部跳过 guard。

## 7. API 约定

- 前缀 `/api/v1`；成功 `ApiResponse.ok/created`；分页 data 用 `PageResult`。
- HTTP：查询 200、创建 201、参数 400、未登录 401、角色 403、不存在或非本人 404、
  时段/状态/幂等冲突 409、业务规则 422、限流 429、锁等待 503。
- 核心写请求要求 `Idempotency-Key: UUID` 头（预约、考勤、申诉、审核、信用调整、资源批量变更）。
- 错误码用 `ErrorCode` 枚举，前端只按 code 分支。
- DTO 用 record；Entity 不得直接作为响应 DTO；不返回密码哈希/现场码哈希/服务器路径。
- ID 在 JSON 中为字符串（Jackson 已全局处理 Long→String）。

# 数据库启用与端到端验证步骤（需操作者注入密码）

本文是**从零重建数据库**的完整操作序列。全流程已于 2026-10-15 实测打通
（迁移、bootstrap 管理员、演示夹具、集成测试 49/49 全绿）；数据库密码只允许由操作者
注入环境变量，不能写入仓库。

## 一次性准备（需建库权限账号，建议 root）

```sql
CREATE DATABASE IF NOT EXISTS studyroom_dev  CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE IF NOT EXISTS studyroom_test CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

-- 应用账号：只给 DML，不给 DDL/DROP/GRANT/FILE（迁移用单独账号或临时授予）
CREATE USER IF NOT EXISTS 'studyroom_app'@'127.0.0.1' IDENTIFIED BY '<自行设定强密码>';
GRANT SELECT, INSERT, UPDATE, DELETE ON studyroom_dev.*  TO 'studyroom_app'@'127.0.0.1';
GRANT SELECT, INSERT, UPDATE, DELETE ON studyroom_test.* TO 'studyroom_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

> 若希望应用账号自身执行 Flyway 迁移，则需额外授予 `studyroom_dev.*` 上的
> `CREATE, ALTER, INDEX, REFERENCES`（仍**不要**给 `DROP`、`GRANT OPTION`、`FILE`）。

## 第 1 步：启动后端（自动迁移）

```powershell
$env:JAVA_HOME = "D:\JDK_21"
$env:DB_USER = "studyroom_app"
$env:DB_PASSWORD = "<上一步设定的密码>"
$env:UPLOAD_DIR = "D:\studyroom-data\uploads"
$env:JWT_SECRET_BASE64 = [Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))

cd "<项目根>\backend"
& "$env:JAVA_HOME\bin\java.exe" -jar target\studyroom-1.0.0.jar --spring.profiles.active=local
```

期望日志：Flyway 依次执行 `V001__schema.sql`、`V002__rule_seed.sql`、`V003__drop_study_room_floor.sql`
→ `Successfully applied 3 migrations` → `Tomcat started on port 8080` → `Started StudyRoomApplication`。

> 端口提示：若 shell 环境存在 `SERVER__PORT` 等 Spring 风格环境变量，会覆盖 `application.yml` 的
> `server.port`（表现为"随机端口已被占用"）；此时显式追加 `--server.port=8080`。

验证：`curl http://127.0.0.1:8080/actuator/health` 应返回 `{"status":"UP"}`（有数据库时才为 UP）。

## 第 2 步：初始化首位管理员（空库仅一次）

另开一个终端（保持第 1 步的服务，或先停掉再执行）：

```powershell
$env:BOOTSTRAP_ACCOUNT = "admin"
$env:BOOTSTRAP_PASSWORD = "admin123"    # 课程演示统一口令（密码策略：6—12 位非空白）；正式环境必须改
cd "<项目根>\backend"
& "D:\JDK_21\bin\java.exe" -jar target\studyroom-1.0.0.jar --bootstrap-admin
```

期望：日志提示「初始密码仅本次由环境变量提供，请立即登录并修改密码」，进程退出码 0。
该账号登录后即可直接使用全部接口（已移除首次登录强制改密）。

## 第 3 步：导入参考数据与演示夹具（仅 local）

```powershell
& "D:\JDK_21\bin\java.exe" -jar target\studyroom-1.0.0.jar --seed-reference-data --allow-demo-fixtures
```

期望：日志输出创建/跳过的房间、座位、学生数量（幂等，可重复执行不覆盖）。
演示学生账号 `20240001`—`20240008`（统一初始口令 `stu123`），现场码 `123456`；进行中订单样本只在开放时间（07:00—22:30）内生成。

## 第 4 步：启动前端并登录

```powershell
cd "<项目根>\frontend"
npm ci
npm run dev
```

浏览器打开 <http://127.0.0.1:5173>：用 `admin` / `admin123`（第 2 步口令）登录 → 进管理后台；
用 `20240001`（口令 `stu123`）登录 → 进学生端选座、预约、签到。
两端右上角用户菜单均提供「修改密码」入口。

## 第 5 步：运行数据库不变量集成测试

```powershell
cd "<项目根>\backend"
$env:TEST_DB_USER = "studyroom_app"
$env:TEST_DB_PASSWORD = "<同一密码>"
& "D:\Maven\apache-maven-3.9.16\bin\mvn.cmd" verify -Pintegration
```

`SchemaInvariantIT` 会校验 6 项不变量：默认规则与 guard 存在、无同座位重叠、无同学生重叠、
信用分 0—100 且流水连续、每单最多一个终态结算与一个违约、现场码非明文。
（2026-10-15 实测：49/49 全部通过。）

未配置 `TEST_DB_PASSWORD` 时该测试类自动跳过，`mvn test`（默认排除 `*IT.java`）仍可通过。
